# CNN_PEP — V4J-SRC: Offline Pinned Source/Asset Bundle (Candidate)

**Status:** Engineering CANDIDATE. This is **not** an executable Vivado snapshot, a compiled/elaborated build, a G0/G6 sign-off, G7 approval, or Full400 authorization.

## Purpose

Following V4f4F (400 synthetic scheduler), V4f4G (400 invocation JSONs), V4H-EXEC (400 offline adapter contracts), and V4I (28 Vivado-authoritative compile entries and source/tool pins), V4J produces **a byte-for-byte local capture** of the authoritative HDL and V4f4F inputs. The copied bytes are stored in a content-addressed, deduplicated directory with an exact SHA256 manifest and read-only second-pass auditor.

The capture protects against loss of source bytes and provides an inspectable G0 supporting artifact. In particular, it copies the **actual `glbl.v` referenced by the pinned compile `.prj`**, not a replacement generated by the patch. It copies the original `.xpr`/`.prj` bytes and records exact compile order, but **does not rewrite absolute paths in the `.prj`**. Therefore the result is **not a portable build-ready project** and cannot serve as executable input to an XSim runner as-is.

## Directory and atomicity policy

The output root must be a **fresh** `fi/results/v4j_*` sibling. The capture writes to `.v4j_<name>.inflight` first, using exclusive file creation and fsync for each copied blob/receipt. The stage is renamed into the final output name only after all copies have been rehashed. On a crash or exception, **the inflight directory is preserved**, never silently recovered or overwritten. A new attempt must be made under a separately named output after forensic inspection; never delete or edit the failed evidence to turn it into PASS.

The content-addressed file path is `blobs/<first-2-hex>/<64-char-sha256>`. Identical input bytes are stored once. Manifest records source paths and roles, bytes, hashes and exact compiled-source order. The capture refuses existing outputs, symlinks/path traversal, source drift, source files above 128 MiB, or an aggregate per-path read set above 2 GiB. It also rehashes all original captured inputs and pinned toolchain wrappers after copying, before publication.

The bundle contents are not cryptographically immutable after the fact; SHA256 replay will detect modification in the audit. **Preserve and externally timestamp/commit the final manifest SHA256** for chain of custody. Copies can include RTL, samples and weights: review ownership/privacy before distributing externally.
