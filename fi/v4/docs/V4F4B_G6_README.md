# CNN_PEP V4f Phase 4B — G6 shadow scheduler/checkpoint qualification

**Scope:** offline Python implementation and tests of a 400-scenario scheduler ledger, **not** 400 FI/XSim experiments and **not** an authorized Full400 runner. This patch only **adds** two Python scripts and documentation to the repo; it changes no RTL, TB, manifest, target status, golden, previously PASS evidence or V4f4 prepared core.

Phase4A's `protocol_core.json` has been verified for integrity, but **G7 remains pending manual independent attestation**. Accompanying `V4F4B_G7_INTERPRETATION_ANNEX_CANDIDATE.md` is a review proposal addressing L2 stage status, denominators and watchdog interpretation. It does **not** freeze the core.

## What the new G6 tool does

- Uses the existing frozen scenario CSV, 20 targets × 10 images × 2 A/B configs, with SHA256 validation and immutable scenario IDs.
- Plans **16 exact batches of 25** with no holes or repeated IDs; records per-batch digests, frozen SHA256 and parent evidence digests.
- Read-only preflight replays V4e raw ancestry, Phase 1 400-plan, Phase 2 **eight real XSim** smoke logs and audit, Phase 3 review, and Phase 4A **prepared-only** G7 hashes. These pre-existing eight XSim logs are *source evidence*, not generated by the tool.
- Executes a **synthetic 400-event engine probe** to stress the checkpoint ledger. Each event explicitly says `SYNTHETIC_CHECKPOINT_NOT_FI_NOT_XSIM`; it has no logit, label, outcome or FI_RESULT. Each event is written once, SHA256-pinned; the progress checkpoint is written atomically. A disk failure between an event and its commit leaves an orphan or inflight marker that **blocks resume**, rather than erasing or autocorrecting any data.
- Explicit pause and resume may occur at any checkpoint boundary (`--pause-after 137`, for example), including between batches. Re-reads prior event hashes and replay provenance before continuing. Files are append-only per attempt, with an OS writer lock.
- An independent `audit` mode validates all 400 synthetic event hashes, the source/evidence pins and ledger; it does not invoke Vivado and writes a separate immutable audit receipt.
- `--execute`, `--approve` and `--mode full400` are **unconditionally forbidden**.

**Qualification limits:** This establishes offline engineering confidence in selection/checkpoint/fail-closed behavior. It does **not** demonstrate real mid-XSim crash or power-loss recovery, sufficient timeout/failure taxonomy for a 400-FI campaign, production build-once/reuse across 400 real simulations, or G6 signoff. The old V4f2 runner is still restricted to its 8-run smoke. `full400_runner_qualified` remains **false** in every output.

## Install and tests (Windows PowerShell)

Extract patch at repo root. Check paths in the ZIP before extracting; there should be **new** files only. Do **not** use `-Force` to overwrite existing project files.

```powershell
Expand-Archive `
  -Path ".\\cnn_pep_v4f_phase4b_g6_shadow_qualification_patch.zip" `
  -DestinationPath .

python -m unittest discover `
  -s fi/v4/scripts -p "test_qualify_g6_v4f4b.py" -q

python -m unittest discover `
  -s fi/v4/scripts -p "test_*.py" -q
```

Run the non-executing full schedule plan (requires all previous Windows evidence directories at their original repo paths):

```powershell
python fi/v4/scripts/qualify_g6_v4f4b.py `
  --mode plan `
  --out-dir fi/results/v4f4b_plan_01
```

Expected marker: `V4F4B_PLAN_PASS: 400/400 frozen tuples, 16 x 25 batches; G7 PREPARED; 0 XSim; FULL400 BLOCKED`.

Run the **synthetic checkpoint engine**; it must not launch XSim:

```powershell
python fi/v4/scripts/qualify_g6_v4f4b.py `
  --mode probe `
  --out-dir fi/results/v4f4b_probe_01 `
  --pause-after 137

python fi/v4/scripts/qualify_g6_v4f4b.py `
  --mode probe `
  --out-dir fi/results/v4f4b_probe_01 `
  --resume
```

Expected: `V4F4B_SHADOW_PAUSED: 137/400 synthetic commits` and then `V4F4B_SHADOW_PASS: 400/400 synthetic scheduler checkpoints; 16 batches x 25; 0 XSim; G6 NOT QUALIFIED; FULL400 BLOCKED`.

Independent read-only verification of the completed probe, with a new output directory:

```powershell
python fi/v4/scripts/qualify_g6_v4f4b.py `
  --mode audit `
  --probe-dir fi/results/v4f4b_probe_01 `
  --out-dir fi/results/v4f4b_audit_01
```

Expected: `V4F4B_SHADOW_AUDIT_PASS: 400 synthetic checkpoints replayed; 0 XSim; FULL400 BLOCKED`.

## Fail-closed, recovery and source integrity

- Do not edit existing PASS evidence. If a new output dir already exists, choose another suffix rather than overwriting it.
- A missing/changed input pin, broken parent ancestry, any `.tmp`, `inflight.json`, orphan `probe_events/*` or another active writer **blocks** resume. Preserve the failed attempt for audit; start a **new** attempt only after reviewing it. `--resume` never repairs or deletes a partial log.
- A scheduled pause is *controlled*, not an abrupt OS/process/power failure. The tests inject artificial exceptions at the inflight/event/commit boundaries in **test-only hooks**; they are not hardware/XSim experiments.
- Pinning old evidence binds tool execution to the original Windows repo location; moving/mounting prior evidence into a different absolute path may require a separate provenance re-qualification. Do not rewrite historical JSON pins.
- If any user-provided script, V4e/V4f1/V4f2/V4f3/V4f4 receipt or source file was changed since prior qualification, stop and investigate instead of treating errors as cosmetic.
